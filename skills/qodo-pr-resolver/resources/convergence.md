# Convergence & Oscillation Detection

This document explains how the PR Resolver avoids the **flip-flop / oscillation** failure mode:
the resolver applies a fix in review round N, Qodo's round N+1 review flags the same code with
the *opposite* suggestion, the resolver applies the reversal, round N+2 flips it back — and the
PR churns for 5–6 rounds without converging.

The fix is simple: **before reverting or re-changing code, the resolver reads its own trail from
prior rounds.** That trail already exists on the PR — it just has to be loaded back in.

## The prior-round trail (where history lives)

Every round, the resolver writes three durable, machine-readable records. None of them need new
storage — they are already on the PR / in the repo:

1. **Fix-summary comments** — top-level PR comments ending with
   `Generated by Qodo PR Resolver skill`. Each lists `### ✅ Fixed Issues` and
   `### ⏭️ Deferred Issues` with titles, severities, and reasons.
2. **Inline replies** — `✅ **Fixed** — …` / `⏭️ **Deferred** — …` replies the resolver posted
   on each Qodo comment thread.
3. **Git history** — `fix: <issue title>` commits on the current branch.

## Loading the trail (Step 3c)

Fetch the resolver's *own* prior records (author = the current git user, or a comment body
containing `Generated by Qodo PR Resolver skill`). Reuse the **same comment-fetch commands from
Step 3** (no new endpoints), plus git log:

```bash
# Prior resolver commits on this branch (T1 unified commit format)
# The subject line is the signature:
#   fix: resolve Qodo review findings
# and the commit body must include structured per-finding lines keyed by file:line.
git log origin/<base-branch>..HEAD \
  --grep '^fix: resolve Qodo review findings$' \
  --format='%H%n%s%n%b%n----'
```

From these (plus prior summary comments and inline replies), build a **decision log** keyed by **`file:line`** — one entry per location the resolver has acted on before.

**Primary key:** `file_line` (e.g., `src/auth/service.py:42`). Always look up new issues by `file:line` first.

| field | meaning |
|-------|---------|
| `file_line` | `path/to/file.ext:<line>` (primary lookup key) |
| `title` | Qodo issue title (verbatim) |
| `decision` | `fixed` / `deferred` / `skipped_to_prevent_oscillation` |
| `intent` | a short descriptor of what changed at that `file:line` (from T1 commit body / inline reply) |
| `rationale` | what was changed / why it was deferred |
| `round` | which prior round (by summary-comment order) |
| `flip_count` | number of prior direction flips at this same `file:line` (see hard stop below) |

## Tagging current issues against the ledger

For each issue parsed in Step 4, compute its **`file:line`** (use the inline comment’s exact line if available) and compare against the decision log at that same key:

- **🔁 Repeat** — the same `file:line` was already **fixed** in a prior round and Qodo is raising it again.
- **⚠️ Contradiction** — at the same `file:line`, the new suggestion would **reverse** a prior applied fix **or** it re-raises something previously `deferred`/`skipped_to_prevent_oscillation`.
- **(untagged)** — no prior entry at that `file:line`; handle normally.

If multiple prior entries exist at the same `file:line`, use the most recent round’s entry for the default behavior, and keep a `flip_count` for escalation.

When the ledger is empty (first round, or history could not be fetched), treat every issue as
untagged and proceed normally. **If history fetch fails, say so** — do not silently behave as if
there is no prior round.

## Behavior for tagged issues

The goal is to **break the cycle**, not to keep applying whatever the latest review says.

### ⚠️ Contradiction
Do **not** auto-apply. Present to the user, in one message:
- the **prior decision** and its rationale (from the ledger, with the round number), and
- the **new contradicting suggestion** (Qodo's current agent prompt).

Default the AskUserQuestion to **Defer** with options exactly: **Defer / Apply / Modify**:
- ⏭️ **Defer** *(default)* — do not auto-apply a reversal; record on the thread that we are deferring to prevent oscillation.
- ✅ **Apply** — apply the reversal/change **only if allowed by the hard-stop rule below**.
- 🔧 **Modify** — user adjusts manually.

When **Defer** is chosen, reply to the thread and resolve it
(`"unresolved": false`) with a rationale that names the prior round, so the next review has the
context recorded on the thread:

> 🛑 **Defer to prevent oscillation** — deliberate prior-round change (<rationale>, round <N>); not reversing automatically. If still a concern, explain why the prior approach is incorrect.

#### Hard stop (3rd+ oscillation cycle at the same location)

Track direction flips per **`file:line`** using the decision log’s `intent` field (from T1 commit bodies / inline replies). If the same `file:line` has **`flip_count >= 2`** (i.e., at least two prior direction flips — the 3rd oscillation cycle), the resolver must **refuse to auto-apply** at that location.

- Even if the user selects **Apply**, do not proceed automatically.
- Only proceed if the user provides an explicit override message (exact text): `OVERRIDE_OSCILLATION_APPLY`. Record that override in the thread reply and in the Step 8 summary.

### 🔁 Repeat
Re-raised after a prior fix. Before changing anything, **re-read the current code** and check
whether the prior fix is still present and correct:
- If the prior fix is intact and the finding looks like Qodo re-deriving it: default to **Defer**
  with reply `⏭️ **Deferred** — addressed in a previous round (<rationale>); no further change.`
- If the prior fix was lost (e.g. a later edit reverted it) or was genuinely incomplete: treat as
  a normal fix.

## Auto-fix mode guard

In **Auto-fix all** mode (Step 7), **🔁 Repeat** and **⚠️ Contradiction** issues are **excluded
from automatic application**. Auto-fix is exactly where unattended flip-flop churn happens, so:

1. Apply only the untagged "Fix" issues automatically.
2. Collect the tagged issues and present them to the user with a **single** AskUserQuestion
   (the Contradiction options above: **Defer / Apply / Modify**, default **Defer**).
3. Report all excluded tagged issues in the Step 8 summary under **"Skipped to prevent oscillation — recommend human resolution."** — never silently skip them.

If any tagged issue hits the **hard stop** (`flip_count >= 2` at the same `file:line`), refuse auto-application unless the explicit override message is provided.
